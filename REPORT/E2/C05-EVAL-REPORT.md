## 3. Implementation summary

### 3.1 Explicit heap frame stack — no C++ call-stack recursion (W7 = 2^16)

`run_chunk_explicit_stack` replaces the recursive evaluator with an explicit
`std::vector<EvalFrame>` frame stack bounded by `limits.wf.max_depth` (65536). A frame
carries its node id, start offset, output span, phase, scratch vector, mirrored-block
buffer, and a small predictor state struct. The 65,536-deep legal term
(`1 atom + 65,535 INVERT8 morphs`) evaluates without call-stack growth; the 65,537 case
is rejected with `Limit` (`o5.3.w7_depth_65536` / `o5.3.w7_depth_65537_limit` PASS; the
unit test `MaxDepth65536EvaluatesOnExplicitStackWithoutOverflow` PASS).

### 3.2 Block-buffered streaming and scratch accounting (O5.3)

Full decode streams through fixed block buffers (`limits.block_bytes`, default 64 KiB)
with incremental SHA-256 at the sink; no allocation is proportional to the declared total
length. A per-session `scratch_pool` (≤ 8 buffers ≤ `kEvalBlock`) recycles chunk buffers.
`EvalStats::peak_scratch_bytes` records the high-water mark; the 64 MiB composite stream
reports `bytes=67108864 peak_scratch_bytes=65536 rss_delta_kib=0`
(`o5.3_64mib_stream`, `o5.3.scratch_bound_64mib`, `o5.3.rss_delta_64mib`).

Range decode touches only intersecting subterms (binary search ≥ 8 args in `Concat`,
modulo arithmetic in `Repeat`, translated offsets in `Slice`); `read_range` allocates
nothing proportional to the length (E2-I9). The 2^70-byte virtual LFSR fixture decodes any
64-byte slice directly (`o5.2.above_2pow64_slice` PASS, offsets above 2^64).

### 3.3 Predictors (§4.11, §5.5)

- `read_range` on a predictor evaluates the residual prefix from 0 (or from the nearest
  checkpoint/rolling state) discarding output, then emits the range. If the gap to the
  nearest known state exceeds `predictor_prefix_max` (default 2^28) the call returns
  `Limit` (`o5.2.pred_prefix_limit` PASS); past-the-end requests on out-of-bounds starts
  return `Invalid` before the limit check (`o5.2.pred_oob_precedence` PASS).
- pid 3/4 with `param ≥ 1` allocate a rolling `param`-byte ring only when `param ≤
  max_predictor_window` (default 2^20) and the index range actually crosses `param`;
  otherwise a zero-ring path serves `i < param ⇒ out[i] = r[i]` with no ring memory
  (`o5.2.pred_window_limit`, `C05Eval.PredictorPrefixLimitAndStrideWindowPolicy` PASS;
  Pass-1 prefix buffering is reported in `peak_scratch_bytes`, e.g. 100 bytes for a
  100-byte prefix with a 2^24-stride predictor — never a 16 MiB ring).
- Per-session rolling cache: ≤ 4 slots per predictor node, ≤ 32 rolling slots total,
  4-slot per-node deduplicating LRU (`store_rolling_pred_slot`). Slots carry `(offset,
  prev1, prev2, window)` so sibling DAG branches reading the same chunk hit `gap == 0`.
  `PredictorCheckpoint` capture/validate/chain API allows exact state restore; the
  discard pass is O(gap) and the checkpoint itself is O(1).

### 3.4 LFSR

GF(2) linear jump-ahead by 64×64 matrix exponentiation in O(log offset)
(`o5.2.lfsr_jump_exact`, `o5.2.lfsr_log_bound` PASS: 2^60 + 999,999 jump with ≤ 130
GF(2) multiplies and exactly 1 jump). Zero-jump streaming is used for sequential reads.

### 3.5 Mirrored and block morphs

Byte-local morphs apply in place with zero scratch; block morphs (SWAP16/32/64) expand
the range outward to the block size and transform whole blocks; mirrored morphs (REVERSE*,
BIT_REVERSE) read the mirrored child range; `REVERSE_BITS` additionally bit-reverses bytes.
`o5.2.virtual_morph_zero_scratch` and the full morph catalogue (9/9) PASS.

### 3.6 WF(ir) on every normative entry point

`eval_stream`, `eval_range`, `read_range`, `TermCursor`, and all `*_digest`/`*_ex`
variants re-verify `WF(ir)` (W1–W8 + `S1.output-cap`) before touching the term; a malformed
input returns `Invalid`/`Limit` (`c05.wf_guard.*` — 6 guards PASS;
`FullWfEnforcedAcrossAllEntryPoints` PASS). Range entry points recompute lengths and never
trust stored ones (E2-I2, E2-I3).

### 4.3 Evidence-harness defects found and fixed during this work

1. **Use-after-free in the C05 gate corpus (fixed).** Corpus items held `Ir` values whose
   `Atom::payload` spans pointed into heap `Builder` payload stores that were destroyed at
   the end of each construction block. Reads then returned allocator-reuse garbage: the
   gate mis-predicted *different digests on every invocation* (verdicts flaky but stable
   per run), while `structural_key` (stored atom SHA-256) kept the `input_sha256` column
   stable — which is what flagged the alias. C03/C04 gates already keep their builders
   alive inside `TermItem`; the C05 gate now keeps its builders alive in
   `Gate::corpus_builders_` for the process lifetime. After the fix, five consecutive
   gate invocations and the ASan/UBSan build produce a **byte-identical** TSV and 162/162
   PASS. The unit tests were never affected (their builders outlive evaluation).
2. **Predictor rolling-state theft across sibling DAG branches (fixed in C03 core).** A
   predictor node evaluated inside `Xor(p, Morph(2, p))`-shaped DAGs beyond
   `predictor_prefix_max` lost its predecessor slot when the first branch zeroed the
   in-memory ring in place; the sibling branch re-scanned from 0 or returned `Limit`.
   `store_rolling_pred_slot` now copies the ring, keeps `best` intact, and deduplicates
   equal `(node, offset)` entries in a per-node 4-slot LRU.
3. **Test expectation errors (fixed).** The W7-depth test and its gate twin used morph id
   `1` (`BIT_REVERSE8`) where the asserted value requires `INVERT8` (id `2`, `~x`);
   `PredictorPrefixLimitAndStrideWindowPolicy` asserted `peak_scratch_bytes == 0` where
   Pass 1 legitimately buffers the 100-byte prefix (it is `100`, with **zero** 16 MiB
   stride ring). Expected values, not code, were wrong.

## 7. What this report does **not** claim

- **E2-G is not claimed.** No pinned KATs (T-KAT/M-KAT), no critical-pair battery, no
  rewrite-rule counters, no `E2-G` verdict of any kind. C05 verifies evaluation, not
  canonicalisation (C04) or term identity (C06).
- **C06 `DAG` is not claimed.** No interning, ordering, or identity-by-construction rules.
- **Constant-time predictor evaluation is not claimed (§5.5 is normative).** Range decode
  on a predictor performs a linear discard pass (bounded by `predictor_prefix_max`) or
  returns `Limit`; checkpoints restore exact state but are not required by any gate.
- **No wire-level behaviour (E3) and nothing E4–E7** was built, linked, or audited; the
  C05 isolation check only proves link/source independence.
- **`ci.yml` and `h1-fixtures.yml` do not trigger on this branch** (branch filters are
  `master`/`main`/`h2-gates` and `h1-fixtures`/`arena/6a99d26f-marp` respectively); their
  jobs were not re-run by this push. Their evidence manifests were verified locally with
  `sha256sum -c` and inside the `e2-c05.yml` independence job on CI.
- The 64 MiB memory-boundedness measurement is one composite fixture (`composite-64mib`)
  plus RSS sampling of this process on this runner; it is not a proof of allocator
  behaviour on all platforms.
- Predictor rolling-cache parameters (4 slots/node, 32 total, 2^28 prefix limit, 2^20
  window cap) are the spec's default limits, not tuned values; `EvalLimits` exposes them.
